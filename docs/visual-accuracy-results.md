# 视觉准确率优化记录（2026-10-09）

已启用“动作观察 → 互动对象判断 → 完整工具决策”的视觉增强。使用原有 UnifoLM-ER-1 服务，未训练或更换模型。输入为真实公开视频帧，不是文字描述或灰图任务。

## 结果

| 数据划分 | 原版严格通过 | 增强版严格通过 |
| --- | ---: | ---: |
| 开发：各类 01–03 | 11/18 | 16/18 |
| 验证：各类 04–06 | 13/18 | 15/18 |
| 独立测试：各类 07–09 | 9/18 | 14/18 |
| 合计（含调试数据，不能当作泛化成绩） | 33/54 | 45/54 |

独立测试严格通过率由 50.0% 升到 77.8%。12 个负例的技能误触发由 2 次降至 0；6 个正例正确回应由 1 次升至 2 次。挥手为 1/3 → 0/3，握手为 0/3 → 2/3。这意味着主要收益来自减少误回应、找回部分握手，**挥手仍不稳定**，不能宣称各种动作都变准。

全部 54 段中：挥手正确数 4/9 → 4/9；握手 2/9 → 5/9；36 个负例技能误触发 5 → 0。严格分数还把空闲时返回 `continue` 判错，即使它和 `ignore` 一样没有触发动作。原版有 4 个这样的负例，新版没有。分项统计在 `evaluations/visual-comparison.json`。

独立测试中位推理延迟约 2.07 → 3.44 秒，包括所有观察调用，不含模拟动作执行时间。原有 5 秒决策时效限制保留；远端排队导致结果过期时仍会拒绝执行。

## 实现和适用范围

- `src/agent/grounded_vision.py`：模型先从连续帧判断动作；出现候选社交动作时再判断互动对象。只将固定枚举的视觉观察传给最终决策，不把模型自由文本当作指令。
- 最终决策仍能看到原图、任务、运行状态、历史和全部 52 个工具及参数；不增加工具标签或权限要求。
- 控制台及通用 remote CLI 根据任务文字自动选择增强：观察、检测、回应挥手/握手等互动时启用；直接工具命令走原来的单次决策。措辞未被识别时也保留原来的通用视觉能力，不禁止工具。
- 这样区分是因为直接命令回归中，盲目附加观察会丢失参数：8 个样例原版 7 个符合预期，强制增强只有 6 个。原版自身也有一个自定义动作漏参数；此次没有把该问题描述为已修复。
- 未启用旧候选 `VerifiedSocialVisionInvoker`：它会明显压低握手召回。单帧、单纯加规则等候选也已淘汰。实验脚本保存在 `evaluations/experiments/`。

## 测试方法与限制

数据来自 NUSFPID，wave、shake、3wave、3shake、cell、type 六类，各取 9 段。每段中间约 2 秒，8 帧，等比缩放到宽 640。模型不可见类别、文件名或答案；每段独立初始化，只运行模拟机器人。模型服务一次只发一个请求，避免 429 干扰结果。

07–09 未用于调整本候选提示。测试分数出来后，没有为这些视频调整视觉提示或观察逻辑。01–06 已用于多次方案选择，不是独立测试。人员/场景在各划分重复，非人物独立划分；样本很少，每个候选每段仅一次，模型输出可能波动。

整段视频动作标签不等于每帧的机器人动作邀请：有些握手已经接触或结束，手也可能出画。`cell/type` 多为佩戴者自己操作设备，不能替代所有面对机器人使用设备的反例。尚未验证击掌正例、连续互动去重、真实深度下的动作完成率。观察器把“正在握手”也视作握手，仍需改进动作阶段识别。

本地 177 项测试通过；机器人端新增 7 项测试通过。测试包括同一图像贯穿各阶段、非可信观察文本不进入决策提示、完整工具目录保留、直接命令路由、最终无效输出仍被拒绝。

## 复现

抽帧需提前提取对应源视频，命令不会覆盖已有目录：

```sh
.venv/bin/python scripts/prepare-nus-vision.py evaluations/my-test --ids 7 8 9
PYTHONPATH=src .venv/bin/python scripts/eval-public-vision.py evaluate evaluations/my-test --grounded
python scripts/summarize-visual-evals.py evaluations/my-test
```

去掉 `--grounded` 为原版。比较时使用不同输出目录，评测会覆盖目录内旧结果。源码固定保存了三个阶段的提示文本，各例保存输入、原始输出、观察结果和计时。NUSFPID 包内许可限学术用途；未重新发布原始数据。
